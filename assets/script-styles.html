lectoria · script styles

Four ways to turn a document into spoken audio

From the most produced (a friendly podcast show) to the most faithful (read the doc as-is), plus a two-voice dialogue mode for NotebookLM-style listening.

🎙️

podcast

most produced

A friendly host rewrites the document as a podcast episode: short welcome, 3–7 chapters, recap, sign-off.

you want the material to feel like a real show.

💬

conversational

default · ~70% fidelity

Natural spoken read-along. No welcome, no sign-off, but the model restructures lists, merges short paragraphs, and adds spoken signposts so it flows by ear.

you want to understand a doc on the go without it sounding like a show.

📖

verbatim

~95% fidelity

Read the document essentially as-is, in the requested language. No invented intro/outro, no host banter, just the doc — lightly cleaned for spoken delivery.

you want to listen now and dig back into the doc later.

👥

dialogue

two-voice · notebooklm-style

Two named speakers discuss the material in natural back-and-forth. Each utterance carries a speaker id so the TTS stage dispatches to the right voice per language.

you want a hosted-feel without a single-narrator monologue.

Pick a style at the CLI with --style <name>, or programmatically via ScriptStyle in the library API. See README for the full reference.
